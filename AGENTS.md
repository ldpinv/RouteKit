# RouteKit maintenance

- This repository is public. Never commit real profiles, subscriptions, proxy credentials, private addresses, certificates or traffic logs.
- Edit Source/<category>.list for manual routing. Surge/ and Egern/ are generated. Build inputs, pinned sources and tests live in .github/; caches and detailed reports stay in .cache/.
- Overseas AI maps to AI; mainland AI to Internal. AI precedes Google/Apple/general categories, Streaming precedes Google, AppleCN precedes Apple. Unknown domains remain on the client's Final policy.
- Preserve exact/suffix boundaries and no-resolve on IP supplements. Do not route entire shared cloud/CDN networks to a business.
- Run python3 .github/routekit.py build, python3 -m unittest discover -s .github and python3 .github/routekit.py check.
- Upstream updates create reviewable PRs, never automatic merges. Keep Actions pinned to commit SHAs. Scripts and modules are maintained separately.
- `managed_sources` / `managed_outputs` in `.github/sources.json` pin the profile's extra public rule lists. Preserve client-specific behavior; native Egern Microsoft output is a deduplicated union, not a replacement by one incomplete source. Do not execute upstream code.
- DNS bindings are generated in `Surge/dns/forward.conf` and `Egern/dns/forward.yaml`. They share ordered Surge-format domain lists (Egern DNS supports this format). Mainland DNS uses an explicit mainland-domain source plus AI-CN/Bilibili/AppleCN, not the whole Internal/DIRECT policy. Optional `Source/dns-domestic.list` and `Source/dns-overseas.list` override DNS only; conflicting overrides fail the build.
- Apple CDN routing belongs to Apple, not AppleCN. Reserve AppleCN for explicit China-specific services; keep Apple Intelligence/PCC in AI. Curated Apple download/media CDN DNS exceptions live in Source/dns-domestic.list independently of routing, using the existing DNS override URL. Do not broaden them to all Apple/whole shared CDN providers or intercept AI. These DNS exceptions are manually reviewed, not an automatic mirror of every upstream CDN addition.
- Keep PR validation read-only and publishing in a separate main-only job. A sync run may attach a successful `RouteKit / generated rules` commit status only after tests/checks passed for those exact generated bytes. Do not auto-approve GitHub's workflow-approval banner, add a PAT, or auto-merge to hide `action_required`.
- Use `.github/review.py` to describe additions, deletions, ownership candidates and DNS changes. Unchanged counts are not proof of unchanged routing. Detailed reports remain in `.cache/`.
